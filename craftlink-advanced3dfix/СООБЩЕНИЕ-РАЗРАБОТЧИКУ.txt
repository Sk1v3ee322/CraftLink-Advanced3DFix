ТЕМА: FilmCraft 0.20.1 / EffectCraft 0.24.1 — CraftLink и Layer Styles на 3D-тексте

Привет!

Прикладываю две независимые доработки к FilmCraft 0.20.1 и EffectCraft 0.24.1.
Патчи сняты с чистых релизных архивов, применяются по отдельности и не пересекаются
по файлам — можно ревьюить и принимать каждую часть независимо.

1. CRAFTLINK — связка FilmCraft → EffectCraft и обратно
   В FilmCraft: правый клик по клипам на таймлайне →
     "Replace with EffectCraft Composition"  — заменяет выделение одним связанным клипом
     "Send to EffectCraft…"                  — отправляет, таймлайн не меняет
   (в русской локали: "Заменить композицией EffectCraft" / "Отправить в EffectCraft…",
   Выделение выгружается в FCP7 XML, рядом кладётся sidecar *.craftlink.json и мастер
   ProRes 4444 с alpha и PCM; EffectCraft открывает это композицией.
   Обратно: примерно через 1 секунду после последней правки (или сразу по File ▸ Save)
   EffectCraft перерендеривает композицию поверх того же мастер-файла, FilmCraft замечает
   изменение через spool-уведомление в %TEMP%\CraftLink и перечитывает медиа. Сохранять
   проект в EffectCraft не обязательно.
   Попутно исправлен баг: терялся fade-out в конце последнего выделенного клипа, когда
   переход стоял на границе выделения (одна сторона внутри, вторая снаружи).
   Обе стороны покрыты регресс-тестами.
   Второй исправленный баг: в проекте, из которого ещё ничего не отправляли, первая
   «Отправка в EffectCraft» падала с голым `os error 3` и ничего не записывала (вторая
   попытка срабатывала). Services::write_file пишет атомарно и не создаёт папки, а папка
   CraftLink создавалась позже — при выпечке мастера. Теперь мост создаёт родительскую папку
   перед записью XML и сообщает путь, если это не удалось. Регресс-тест:
   `the_first_bridge_run_creates_its_link_folder`.

2. LAYER STYLES НА 3D-ТЕКСТЕ — EffectCraft
   Раньше стили (Stroke, Inner Shadow, Drop Shadow, Bevel, Satin, Overlays…) считались по
   плоскому исходнику слоя, а у экструдированного 3D-текста и фигур до рендера не доходили
   вообще: экструзия рисовалась готовыми цветами заливки/обводки, поэтому стили молча
   отбрасывались. Теперь слой рендерится отдельно, стили считаются по этому уже
   отрендеренному изображению (как в After Effects), и результат композитится с учётом
   глубины — то есть стили идут по силуэту объёма. Per-character 3D стилизуется по каждой букве.
   GPU-путь делает то же: read-back кадра на CPU, те же проходы стилей, затем скрытие
   за ближней геометрией. Тест сравнения CPU/GPU: расхождение 0.000 % пикселей,
   max |Δ| = 0.0039 (≈1/255).

САМЫЙ ПРОСТОЙ СПОСОБ — craftlink-patcher.exe
   Один exe, ничего не надо устанавливать: ни git, ни Python, ни сети. Положите его куда угодно:

      craftlink-patcher.exe                     → спросит папку, покажет проверку, спросит согласие
      craftlink-patcher.exe check <папка>       → пробный прогон, ничего не пишет
      craftlink-patcher.exe apply <папка>       → проверка, затем патч (спрашивает перед записью)
      craftlink-patcher.exe uninstall <папка>   → вернуть папку ровно в исходное состояние
      craftlink-patcher.exe revert <папка>      → вернуть только перезаписанные файлы
      craftlink-patcher.exe list                → встроенные патчи
      craftlink-patcher.exe help                → та же справка

   <папка> — корень распакованного релиза, то есть папка с apps/filmcraft/Cargo.toml или
   apps/effectcraft/Cargo.toml. Что это за релиз, он определяет сам; папку можно перетащить в окно.

   Portable-папку или установленную копию пропатчить нельзя: там лежит собранный exe, а патчи
   правят исходники, после чего приложение надо пересобрать. Патчер так и пишет и даёт путь:
   пропатчить исходники, `cargo build --release`, затем скопировать target/release/<product>.exe
   поверх файла в portable-папке (старый сохранить как бэкап).

   Он намеренно строже, чем `patch -p1`:
     - `check` ничего не пишет — все хунки применяются только в памяти;
     - `apply` сначала всё планирует и отказывается трогать хоть один файл, если хотя бы одна
       строка контекста не совпала, и называет файл, строку, что ожидалось и что найдено. Так что
       полупатч на чужой папке невозможен;
     - перед перезаписью каждый файл копируется в _craftlink-backup/<дата>/ внутри папки релиза,
       а имена созданных файлов записываются туда же, поэтому откат получается полным;
     - после записи каждый файл сверяется по sha256 с FILES.txt, и результат печатается:
       «Verified against FILES.txt: 25 file(s) ok, plus 2 root document(s)» для FilmCraft,
       20 + 2 для EffectCraft. Расхождение — ошибка, а не предупреждение.

   Ожидаемо: 27 записанных файлов для FilmCraft (23 замены + 4 новых — два .md-документа и два
   новых .rs) и 22 для EffectCraft (19 замен + 3 новых). `uninstall` — настоящий откат: возвращает
   перезаписанные файлы, удаляет добавленные и подчищает опустевшие папки, то есть дерево
   возвращается в состояние релиза. Проверено сравнением дерева целиком: было 3487 файлов, стало
   3487, ничего не пропало, не появилось и не изменилось. `revert` — узкий вариант: возвращает
   только перезаписанные файлы, добавленные оставляет на месте и пишет об этом.

   Внутри exe лежит копия трёх патчей и FILES.txt, поэтому после перегенерации патчей его надо
   пересобрать: `cd patcher && cargo build --release`. `cargo test` там прогоняет двенадцать
   тестов: два падают, если патч и встроенный FILES.txt разойдутся, один — если патч перестанет
   разбираться, ещё один держит текст отказа для portable-сборки.

   ДЛЯ ТЕХ, У КОГО НЕТ RUST — CraftLink-Installer.exe (лежит в craftlink-quick-patch/,
   исходники в installer/)
   Патчер правит исходники, поэтому ему всё равно нужен cargo, чтобы получить программу.
   Установщику — нет: две готовые сборки вшиты в exe через include_bytes!, поэтому он ставит
   копированием, а не сборкой. Человек указывает portable-папку и всё.

      CraftLink-Installer.exe                     → найдёт, покажет, спросит
      CraftLink-Installer.exe check <папка>       → пробный прогон, ничего не пишет
      CraftLink-Installer.exe install <папка>     → заменит программу (сначала бэкап)
      CraftLink-Installer.exe uninstall <папка>   → вернёт предыдущую программу
      CraftLink-Installer.exe list                → что лежит внутри
      CraftLink-Installer.exe help                → та же справка

   <папка> — это PORTABLE-папка (filmcraft.exe / effectcraft.exe рядом с portable.txt).
   Он смотрит также на один и два уровня ниже, поэтому подходит любой уровень распаковки
   name/name/, а если указать папку с обоими продуктами — поставит оба за один прогон.
   Перетаскивание папки на exe делает то же самое.

   Он отказывается, а не угадывает: программа, уже лежащая в папке, должна совпасть по SHA-256
   с официальной сборкой (хеш закреплён для каждого продукта), поэтому другая версия или уже
   изменённая сборка останавливаются, а не перезаписываются. Вся работа проверяется до первой
   записи — если хоть одна папка не подходит, не меняется ничего и нигде. В каждой папке
   меняется ровно один файл; data/, portable.txt, лицензии и *-cli.exe не трогаются. Старая
   программа уходит в _craftlink-backup/<дата>/ с REPLACED.txt, а uninstall возвращает
   официальные байты точно (проверено на чистых релизах). `cargo test` в installer/ гоняет
   пятнадцать тестов.

   Цена — размер: ~182 МБ (~67 МБ в zip) против 643 КБ у патчера, потому что внутри сборки на
   72,3 МБ и 109,2 МБ. Внутри ровно то, что дают патчи, поэтому патчи остаются главными.

ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ (честно)
   - CraftLink не покадровый: рендер через 1 с тишины, по File ▸ Save или по
     file.craftlinkSync. Один рендер за раз: правка во время рендера запоминается и
     рендерится после.
   - Live-link живёт только в десктопной сборке (в браузерной версии нет фонового потока).
   - autoSync:false отключает автообновление для конкретной связи.
   - 3D-стили: один read-back на кадр на каждый стильный экструдированный слой.
   - Per-character стили считаются по каждой букве, а не по общему силуэту слова —
     осознанный компромисс, плоскости букв в 3D не образуют единого силуэта.

Скриншоты «до/после» для 3D-стилей лежат в архиве, в screenshots/: в релизе без патча красный
Stroke включён, но не рисуется (красная рамка — это выделение слоя), а с патчем обводка идёт по
каждой букве. Ракурсы разные, так что это иллюстрация; настоящая проверка — самому покрутить
камеру.
